# 稳定币数据集检查报告

> 本报告记录适配前的数据检查。现已完成导入适配，下文“当前后端的接入差异”保留为设计依据；当前操作步骤见 [导入说明](import-coingecko.md)。

检查日期：2026-10-27。对两个压缩包中的 111 个 Parquet 行情表、对应 JSON 元数据及全部 2,934 条 JSONL 新闻做了全量读取和统计。未修改压缩包、未导入 MySQL、未更改业务代码。时间均为 UTC。

## 结论

这批数据可以用于网站的历史价格展示。应先接入 USDT、USDC、DAI 的每日价格；小时行情、日价格快照和新闻需要按各自的真实字段建模。当前 CSV 导入器和 candles 表不能直接承接全部数据。

| 内容 | 资产数 / 记录数 | 实际时间范围 | 格式 |
| --- | --- | --- | --- |
| 小时 OHLC | 84 个资产 / 1,233,413 条 | 2019-05-25 至 2026-09-29 | Parquet + JSON 元数据 |
| 每日价格、市值、24 小时成交额快照 | 27 个资产 / 48,284 条 | 2018-01-01 至 2026-09-28 | Parquet + JSON 元数据；位于新闻压缩包内 |
| 新闻与指南元数据 | 2,934 条 | 2019-01-30 至 2026-09-28 | JSONL + manifest |

两个行情集合的 CoinGecko coin_id 没有交集，共 111 个不同 ID。各资产的实际起止时间不同；元数据中的请求区间不等于每个资产都有该区间的完整记录。

## 字段与质量

小时表字段为 timestamp、open、high、low、close、volume。时间戳为 UTC、精度毫秒，实际落在整点。所有表按时间升序，同一资产无重复时间戳；行数、首末时间与元数据一致。

- 1,233,413 条记录的开、高、低、收均没有空值、无穷值、零或负值；OHLC 大小关系检查通过。这些结构检查不等于每个价格已由第二数据源验证。
- volume 全部为空：1,233,413/1,233,413，不能当成真实零成交量。
- 76/84 个资产的首末时间之间存在小时缺口，共缺少 68,251 个小时网格点。

日行情字段为 timestamp、price_usd、market_cap_usd、volume_24h_usd。这是每日价格快照，不包含真实的每日开、高、低、收。所有表升序、无重复日期，字段无空值和无穷值，价格全部为正。

- 15/27 个资产存在日缺口，首末日期之间共缺少 1,798 个日网格点。
- USTC（terrausd）从 2022-04-24 跳至 2022-05-23，2022-04-25 至 2022-05-22 共 28 天没有记录；这些日期不能通过插值当成真实观测。
- ESD（empty-set-dollar）有 264 条 market_cap_usd = -1；属于不可直接使用的市值值，应保留原始值并标记无效。
- 日行情中共有 4,380 条零市值和 46 条零成交额。零值与缺失值应区分，并按数据来源核对含义。
- 按浮点数最短十进制文本转出时，1,313 条价格（ESD 369、IRON 903、USTC 41）以及 2 条成交额的小数位超过 18 位。当前 DECIMAL(38,18) 和导入校验不能原样接收这些文本，需要明确精度与保留原值的策略。

缺口只按每个资产的首末观测之间、每小时或每日网格计算；没有把上市前的时间算成缺失。缺口原因不能仅靠这些文件确定。

## 当前后端的接入差异

1. cmd/import 当前只读 CSV，要求时间、open/high/low/close/volume；不能直接读取 ZIP/Parquet，也不能直接读取新闻。
2. candles.volume 当前是 NOT NULL，Go Candle.Volume 也是必填字符串。小时数据需要支持空成交量及质量标记，不能先填 0 绕过校验。
3. 建议为日行情增加独立的 market_snapshots（每日市场快照）存储与查询，保留 price_usd、market_cap_usd、volume_24h_usd 的含义。单个每日价格点不能恢复真实 K 线。
4. 资产应使用来源与 coin_id 建立唯一映射，币种简称仅用于展示；链和合约地址没有从本数据集得到确认。
5. 小时元数据没有记录 vs_currency、链或合约地址，也没有锚定币种配置。资产包括 EURC、JPY Coin 等，应逐项核对报价币种与锚定对象，再计算脱锚程度。
6. CoinGecko 文档定义 /ohlc/range 的 timestamp 为 K 线收盘时刻，而当前表字段叫 open_time。接入前要统一时刻含义、保存来源语义，避免错移一个周期。
7. 数据最新到 2026-09-28/29。当前 API 默认查询最近 24 小时，在 2026-10-27 会查询不到这些历史数据；需要显式传入历史日期。31 天的查询上限也需要配合分段查询或为长期历史另设接口。

官方字段含义：[OHLC 时间范围接口](https://docs.coingecko.com/reference/coins-id-ohlc-range)、[价格/市值/24 小时成交额接口](https://docs.coingecko.com/reference/coins-id-market-chart-range)。

## 新闻使用边界

- 共 2,934 条，按 URL 无重复；有 14 条额外的同名标题记录，标题相同不代表一定是同一篇文章。
- 包含 2,912 条 news 和 22 条 guide；所有记录都没有正文或摘要字段。可先展示标题、链接和发布时间。
- author 有字符串、数组和空值三种类型；1,283 条作者缺失，326 条来源名缺失，91 条图片缺失，需要统一字段类型与展示规则。
- manifest 设置每个币最多 400 篇，DAI 已达 400 篇，因此不能据此认定新闻历史已完整。
- 发现标题提到 Berachain / Bera USD 的记录，却带 matched_coin_ids=[binance-usd]，需要复核关联规则。现有标签不能直接当作事件的人工真值。

## 建议接入顺序

1. 先接入 USDT、USDC、DAI 的日价格快照，做历史价格查询；这三个资产各自首末日期内没有缺日，价格字段可用。
2. 接入其他日价格，保留缺口，对无效市值单独标记。USTC 的缺失区间需补源后再做相关事件回放。
3. 支持小时 OHLC、空成交量以及报价/锚定信息，展示真实小时 K 线。
4. 新闻按独立记录接入，复核币种关联；需要正文分析时另行补充正文。
