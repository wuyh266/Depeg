# 网页与历史阈值检测

更新日期：2026-11-03。网站由现有 Go 服务提供。首次更新需显式运行 cmd/migrate，新增 monitor_rules、monitor_events 两张表，原行情表不改写。

## 使用顺序

1. 启动 MySQL，在项目目录执行 `go run -buildvcs=false ./cmd/migrate`，再执行 `go run -buildvcs=false ./cmd/api`。
2. 打开 http://127.0.0.1:8080/，注册或登录。用户名为 3–32 位英文、数字、下划线、点或短横线；密码为 8–72 UTF-8 字节。
3. 在市场总览中搜索币种，或按记录状态筛选。币种以资产 ID 区分，同名代码不会合并。
4. 进入详情，切换数据来源与日期范围。日快照可看价格、偏离、市值和 24 小时成交额；OHLC 展示该周期收盘价，不把快照伪造成 K 线。
5. 确认锚定价、预警阈值和严重阈值后保存。锚定价使用当前所选来源的报价货币；日快照报价为 USD。默认表单阈值为 0.5% / 1%，锚定价未知时留空。
6. 点击“检测当前区间”，保存超过阈值的源观测。结果可在详情或“阈值记录”页查看；“导出 CSV”导出当前图表实际读取的全部记录。

当前没有自动外部采集或定时告警。“刷新数据”重新读取本地 MySQL；区间检测只在用户点击时执行。

## 偏离与边界

偏离 bps = (记录价 − 锚定价) / 锚定价 × 10,000。1 bps = 0.01%。正数表示高于锚定价，负数表示低于锚定价。后端使用 math/big.Rat 精确比较，再把显示值舍入到 6 位小数；判断不基于舍入值。

绝对偏离达到严重阈值为 critical；否则达到预警阈值为 warning；否则为 stable。锚定价、记录价必须为正十进制；锚定价最多 20 位整数和 18 位小数。阈值以整数 bps 存储，要求 1 <= warning < critical <= 100000。

每条事件代表一条超过阈值的观测，不是推断出的脱锚开始、结束或持续时间。连续命中不能当作多个独立事件。缺失数据期间不推断恢复状态。

## 规则、隔离与幂等

- 规则主键为 user_id + asset_id；同一个用户对一个资产保存一套规则，绑定 kind、source 和 interval_seconds。
- 用户身份只取 JWT 中间件验证后的账号，忽略客户端提供的 user_id；所有规则和事件查询都带账号条件。
- 锚定价规范为 18 位十进制，使用规则内容生成版本摘要；相同数值的 1 与 1.00 对应相同版本。
- 事件 ID 由用户、资产、规则版本和源记录时间生成；相同规则重复扫描不会重复写入。
- 保存事件前在事务内锁定规则行，核对版本，再分批写入。检测过程中规则改变返回 409，整批不提交；任意一批失败也回滚全部事件。
- 规则改变保留旧事件；事件保存锚定价、阈值、来源、周期、观测时间、检测时间与规则版本。重新导入修正后的行情不会改写已保存的事件，旧事件代表检测当时看到的价格。

## 数据口径

总览以来源自身的最后观测为准；有个人规则时选择其绑定来源，否则优先日快照，再选择已存 OHLC。不同来源不平均、不拼接。覆盖范围和记录数由数据库聚合得到，避免每个币种分别拉取整个历史。

日快照保留原始观测时间。OHLC 横轴为区间开始时间，最新观测时间优先采用 source_time；缺失时采用开始时间加周期。超过三个采样周期标记为历史记录；未来观测另行标明。最新一条历史异常不代表当前市场仍异常。

查询区间为 [from,to)，日期控件结束日期包含当天，实际结束时间截断到当前时刻。OHLC 单次最长 31 天，日快照最长 3660 天，单次最多 50,000 条，检测处理超时为 10 秒。

市值/成交额缺失保留 NULL；OHLC 的 volume 不作为 USD 24 小时成交额。图表缺口断线，不补零、不插值。显示采样保留局部极值，原始记录仍用于统计及 CSV。图表和格式化统计为展示值；精确判断以服务端为准。

## 接口

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | /api/v1/dashboard | 总览、来源覆盖和当前用户规则 |
| POST | /api/v1/monitor/rules | 保存或更新当前用户的资产规则 |
| POST | /api/v1/monitor/replay | 按保存的规则检测历史区间 |
| GET | /api/v1/monitor/events | 分页读取当前用户记录，可按 asset_id 筛选 |

全部接口需 Bearer access token，响应 no-store。事件按 observed_at + id 倒序游标分页；游标绑定用户与资产筛选，limit 范围 1–100。JSON 结构见 api/openapi.yaml。

## 开源参考的取舍

参考 [Pharos](https://github.com/TokenBrice/pharos-watch) 的总览、详情、历史记录和时间信息组织，参考 [depeg-monitor](https://github.com/kcolbchain/depeg-monitor) 的显式阈值思路。页面、图表和 Go 检测代码为本地实现，没有复制其完整前后端或引入其部署依赖。

[DefiLlama peggedassets-server](https://github.com/DefiLlama/peggedassets-server) 作为后续发行量、链分布等数据适配的参考。本阶段沿用已适配的 CoinGecko 历史数据；没有增加外部采集、Cloudflare、Redis、钱包或交易功能。论文模型推理单独预留。
