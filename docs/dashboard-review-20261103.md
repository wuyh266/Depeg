# 本次实现取舍与 Review

日期：2026-11-03。范围为既有 Gin / GORM / MySQL 项目的本地网页、个人阈值规则、历史命中记录。保留现有接口、JWT 与数据导入流程。

| 内容 | 采用的方式 | 取舍与后续 |
| --- | --- | --- |
| 页面组织 | 参考 Pharos 的总览、详情、历史记录与数据时间展示 | 先交付能查看真实导入数据的本地网站，不整体迁移其 Cloudflare 后端 |
| 前端栈 | 原生 HTML/CSS/JS + SVG，由 go:embed 嵌入服务 | 无 npm/CDN/独立前端运行时；组件规模扩大时可迁移到前端框架，现有 API 可继续使用 |
| 认证 | 沿用 JWT 与 MySQL 会话；网页按标签页保存令牌，单次刷新轮换 | 不保存密码；后续面向公网时完善登录限流、HTTPS 与部署配置 |
| 监测方式 | 参考 depeg-monitor 的显式阈值，由用户发起历史区间检测 | 当前不运行实时采集、后台定时检测或外部消息通知 |
| 锚定价 | 来源已有确认值或个人规则；未知时留空 | 不默认为所有资产锚定 1 USD；个人设置不覆盖全局资产元数据 |
| 阈值计算 | math/big.Rat 精确比较，达到阈值即命中 | 显示 bps 保留 6 位小数；展示舍入不会改变等级判断 |
| 规则范围 | 每账号、每资产一套规则，绑定来源及周期 | 不同账号互不影响；同一用户若需多套并行策略，可后续增加规则 ID |
| 事件语义 | 每条超阈值的实际观测为一条记录 | 不推断脱锚起止、恢复或持续时间；避免在有缺口时产生虚假事件边界 |
| 写入一致性 | 版本摘要 + 确定性事件 ID + 行锁 + 整批事务 | 重复检测不重复写入；规则改变时旧检测拒绝提交；旧版本记录保留 |
| 修正数据 | 历史事件保留检测当时的价格和参数 | 行情重新导入后不覆盖旧事件；需要修订审计时可后续增加数据版本维度 |
| 历史查询 | 复用日快照/OHLC 接口，拉取全部分页后统计和导出 | 保留后端 31 天 / 3660 天限制，单次最多 50,000 条；大范围应分段 |
| 图表显示 | 单一来源、保留局部极值的采样、缺口断线 | 显示使用浏览器浮点；CSV 保留原始十进制字符串和空值 |
| 数据来源 | 继续使用已完成适配的 CoinGecko 历史数据 | DefiLlama 仅作为后续发行量、链分布等数据接入参考，本次没有调用其外部接口 |
| 模型 | /risks 继续预留并返回 503，页面明确未接入 | 论文推理需后续核对特征、scaler、checkpoint 与时间对齐后单独实现 |
| 工程依赖 | 新增代码无第三方运行时依赖；继续使用 Go、Gin、GORM、MySQL | Redis、分布式锁、消息队列与 worker 保持未启用 |
